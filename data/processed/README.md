## Known Issues

### 1. `intersection_analysis.json` vs `final_hotspots.geojson` Mismatch

**Problem**: `intersection_analysis.json` reports `n_hotspots: 0`, but `final_hotspots.geojson` contains 14 hotspot features.

**Root Cause**: The `final_hotspots.geojson` was likely generated with a prior set of parameters (or via manual editing) that differs from the `intersection_analysis.json` run. The JSON analysis file reflects the last pipeline run where the `min_area_sqm=10,000` and `min_overlap_ratio=0.15` filters produced zero passing hotspots.

**Impact**: The demo Flask app (`app.py`) reads from `final_hotspots.geojson` and works, but the pipeline is **not reproducible** from raw inputs to this exact output.

**Resolution Plan** (see `docs/REVISION_PLAN.md`):
- Stage 0: Re-run the full pipeline with current parameters to produce synchronized outputs, OR
- Mark `final_hotspots.geojson` as a demo fixture and clearly document it as such.

### 2. 2024 Taxi Data = Zone-Centroid Approximation

**Problem**: The 2024 NYC Yellow Taxi data (`yellow_tripdata_2024-*.parquet`) only contains `PULocationID` and `DOLocationID`, not real pickup/dropoff coordinates.

**Current Workaround**: Each trip is mapped to the centroid of its taxi zone via the TLC zone shapefile. This means all trips within the same zone collapse to the same spatial point.

**Implication**: The "precision" of taxi-derived hotspots is **inflated**—clustering and scoring appear more spatially specific than the data actually supports.

**Fix in Progress**: A 2014 Yellow Taxi coordinate-level experiment is being developed (see `docs/NYC_2014_COORDINATE_TAXI_COMPARISON_PLAN.md`) to validate whether real coordinates produce materially different hotspots.
